    54→- Key decisions:
    55→  - Approval endpoint advances project.stage to NEXT pipeline stage; chief_director.advance dispatches to the CURRENT project.stage's agent (post-approval). This avoids the off-by-one skip bug.
    56→  - All LLM JSON parsing uses llmJson/safeJson — graceful fallbacks to minimal structures rather than crashing.
    57→  - Already-parsed arrays from LLM output are coerced via a local asArr() helper (NOT jparseArr which expects a JSON string).
    58→  - Story_architect and script_writer take a `stage` discriminator param (mapped from ctx.input.stage in dispatcher).
    59→  - chief_director with action="advance" refuses if current stage has a pending approval gate.
    60→  - "assets" stage dispatches to generateAssets() (chief_director sub-action) rather than knowledge_curator directly.
    61→- Gotchas / frontend contract:
    62→  - POST /api/agents/run body = { agentType, projectId?, input? }
    63→  - story_architect input: { stage: "outline" | "expanded" } (default "outline")
    64→  - script_writer input: { stage: "draft" | "final" } (default "draft")
    65→  - chief_director input: { action: "interview_questions" | "advance" | "generate_assets" } (default "advance")
    66→  - publishing_manager input: { publishAt?: ISO string }
    67→  - analytics_scientist input: { metrics?: Partial<MetricsLLM> } override
    68→  - opportunity_hunter input: { niche?: string } (default "AI infrastructure")
    69→  - POST /api/opportunities body = { niche? } — runs opportunity_hunter and returns the new OpportunityRecord
    70→  - POST /api/approvals/[id]/decide body = { decision: "approved"|"rejected"|"revised", feedback? }
    71→- webSearch can rate-limit (429) under rapid calls; agents handle gracefully (empty results → LLM still produces structured output).
